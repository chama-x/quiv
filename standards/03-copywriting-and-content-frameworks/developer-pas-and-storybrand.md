# ✍️ Developer PAS & StoryBrand Copywriting Frameworks

> **How to apply battle-tested copywriting formulas (Problem-Agitate-Solve and StoryBrand) to open-source developer tooling, speaking directly to senior engineers without corporate marketing fluff.**

---

## 1. The Developer PAS (Problem-Agitate-Solve) Model

Developers are inherently skeptical of marketing language. The PAS framework works because it begins by acknowledging real technical pain that developers experience daily before presenting the solution.

```
┌────────────────────────────────────────────────────────┐
│ 1. PROBLEM  → Identify specific, acute developer pain   │
│ 2. AGITATE  → Detail the compounding consequences       │
│ 3. SOLVE    → Present the clean, deterministic solution │
└────────────────────────────────────────────────────────┘
```

### Applied Example: `quiv`

#### 1. The Problem
> *"When AI coding agents (Claude Code, Cursor, Copilot) build full-stack features, they re-invent domain logic from scratch or copy-paste thousands of lines of code into their context window."*

#### 2. The Agitation
> *"This causes massive context degradation, token exhaustion, hallucinatory regressions, and inconsistent architectures across your organization's repositories. Your monthly API bills spike while your agent's reasoning capacity collapses under 50k+ token prompts."*

#### 3. The Solution
> *"quiv provides a lightweight 5-tier architecture registry and progressive disclosure CLI that feeds agents only the precise 200–800 tokens of architecture primitives they need. Zero context bloat. Deterministic domain models. Reusable software knowledge."*

## 2. The Open-Source StoryBrand Framework

Donald Miller’s StoryBrand framework positions the **developer as the hero** and your **repository as the trusted weapon/guide**.

| StoryBrand Element | Traditional Corporate Pitch | **Developer Open-Source Adaptation** |
| :--- | :--- | :--- |
| **The Character (Hero)** | "We are the leading AI platform" | **The Software Engineer / AI Agent Architect** |
| **The Villain (External Problem)** | Lack of modern software | **Context Window Bloat & Fragile Monolithic Frameworks** |
| **The Internal Frustration** | Inefficiency | *"I'm tired of debugging the same broken architecture patterns in every AI session."* |
| **The Guide (Empathy + Authority)** | "Our proprietary AI engine" | **`quiv` CLI + 5 Capability Tiers + Benchmarked Token Reductions** |
| **The Plan (The Process)** | 10-step enterprise sales cycle | **`bunx quiv find` $\rightarrow$ `quiv use` in 1 command** |
| **Call to Action** | "Book a demo" | **`⭐ Star on GitHub` / `bunx quiv list`** |
| **Success (The Transformation)** | Higher ROI | **10-32x Token Efficiency, Fast Deterministic Builds, Clean Modular Repos** |

## 3. The Developer Vocabulary & Tone Matrix

To establish instant technical credibility:

### Words to Delete vs. Words to Use

| ❌ Banned Marketing Fluff | ✅ High-Trust Developer Vocabulary |
| :--- | :--- |
| "Next-generation / Revolutionary" | **"Deterministic / Type-safe / Zero-runtime overhead"** |
| "Blazing fast" (without numbers) | **"Sub-10ms query execution / 10–32x token reduction"** |
| "Seamless / Frictionless" | **"Single-binary / Zero-dependency / Progressive disclosure"** |
| "Empowers developers" | **"Automates AST transformations / Resolves dependency graphs"** |
| "All-in-one platform" | **"Composable primitives / Headless architecture"** |
